# Vernia Labs

The physical AI research website at https://vernia.in, published from `main` through GitHub Pages.

## Local preview

Run `python -m http.server 4173` in this directory and open http://localhost:4173. No build step or package installation is required.

## Files

- `index.html`, `home-dreamy.css`, `home.js`: the homepage (redesigned 2026-11-15). One painted sky runs behind the hero, the two devices and the game; the page closes on a second sky with the pilot form.

- `assets/sky/`: the sky paintings, generated by `tools/sky.py` (wide band) and `tools/sky_tall.py` (hero, hardware and game). Both need numpy and Pillow: `python3 tools/sky_tall.py 2400 3200 out.jpg 11`.
- `assets/vendor/`: Three.js 0.170.0 plus `GLTFLoader.js`, `BufferGeometryUtils.js`, `RoomEnvironment.js` and `RoundedBoxGeometry.js`, with imports rewritten to the local module (MIT).
- `hardware.html`: redirects to `/#hardware`. The separate Grip One CAD explorer was removed on 2026-11-15; `app.js` remains for the menu on the older pages.
- `waitlist.html`, `waitlist.js`: the earlier standalone waitlist. Still live; the homepage pilot form posts to the same Worker.
- `analytics.js`, `analytics.css`, `analytics-session.mjs`: consented first-party analytics. CTA clicks count links to the waitlist and any element with `data-cta` or `data-interest`.
- `backend/`: the `vernia-waitlist` Worker (waitlist, admin dashboard, analytics collector, outbox mail). See `backend/README.md`.
- `cinematic-motion.js`, `gesture-rig.js`, `assets/models/gesture-hand/`: archived, not loaded.
- `CNAME`: the custom domain; keep it.

## Homepage

1. Hero: "Robot hands learn from human ones." with Plan a pilot (scrolls to the form) and Try Grip One (scrolls to the game).
2. Hardware: Grip One and View One float over the clouds. Drag (or arrow keys) turns each one; a tap or Enter closes Grip One's jaws. Callout lines track named parts of the model every frame; they fade out while a device is being turned and return once it drifts back to its labelled pose. Labels name the parts in the current build: Waveshare IMX219-160, 2 × Arducam B0332 (OV9281), Bosch BMI270, AS5600, RP-C10-LT with an ADS1115. On phones the callouts become a list. Grip One's Raspberry Pi, battery board and their fasteners are hidden in the render (`HIDDEN` in `home.js`).
3. Game: put the apple and the orange in the bowl (on touch screens, tap a fruit, then tap the bowl), on a table held up by four small jet thrusters. The camera distance is solved each resize so the table, the flames and the hovering gripper stay in frame as close as possible. Mouse or arrow keys aim, the mouse button or Space grips; on touch, drag to aim and hold the grip button. A wrist-camera inset renders from Grip One's camera mount. Fruit released over the bowl or its rim rolls in; fruit dropped on other fruit slides clear.
4. Episode report: appears once both are in the bowl. Pipeline steps, a per-stream table, one LeRobot v3 training row, the dataset layout with `meta/info.json`, and every frame. Durations, frame counts, jaw range, idle frames and acceleration come from the visitor's own episode. Part names, rates, resolutions and bitrates are the `PARTS` constant at the top of `home.js`.
5. What we do, where we record, what every lot includes.
Phones: the 3D views render at up to 1.25× pixel density, the game uses 1024 px shadows, the two showcase models draw at 30 fps unless touched, the game lets vertical swipes scroll the page, and the recording panel is a compact two-column block.

6. Plan a pilot: name, work email, optional organisation, interests (`data`, `grip-one`, `headset`) and consent, protected by Turnstile, posted to the Worker with `source: 'home'`. "Reserve" buttons pre-select the matching interest. No payment is taken.

### Signup behavior

Email and at least one interest are required, along with explicit update consent. Name and organisation are optional. The backend normalizes email, uses bound SQL parameters, restricts request size, checks origin, validates Turnstile success/hostname/action, and applies a per-IP limit of five attempts per minute per Cloudflare location. Cloudflare rate limits are approximate, not a strict global quota. Raw IP addresses are not stored in D1.

The database assigns increasing signup numbers. A repeated email keeps the original record and cannot change its interests or retrieve its number without authentication. Concurrent duplicate submissions cannot create multiple records. The UI reports success only after a database write or a verified duplicate lookup path. Signup numbers are not promised delivery positions. New signups enqueue an automated confirmation from team@vernia.in through Spacemail. Duplicate submissions do not resend it. Email ownership is not verified, so report these as submitted leads, not confirmed customers.

Open https://admin.vernia.in/admin to view the private queue and delivery status. Administrative record changes remain in D1. Use `backend/reports.sql` for daily signups, interests, source/campaign breakdowns, and the waiting list. Do not publish query results or customer exports. An operator can mark contacted/invited entries, correct preferences after verifying the requester, or delete a specific record on an authenticated removal request. Keep database exports outside this public repository. D1 recovery is managed through Cloudflare; the source schema is not a customer-data backup.

### Traffic measurement

Cloudflare Web Analytics is installed explicitly on all five public HTML pages. GitHub Pages serves this hostname directly, so automatic Cloudflare proxy injection does not reach the site. The public beacon token is not a secret. The dashboard should use `Exclude bots = Yes`. Browser visits, page views, referrers, countries, devices, and page performance are separate from raw edge requests.

The page does not send email/name/organisation to Web Analytics. Browser analytics remain estimates: script blockers can suppress visits and sophisticated bots can execute JavaScript. A signup is a stronger expression of interest but is not a verified email owner or paying customer. There is no fingerprinting, advertising pixel, or bespoke visitor cookie.

Waitlist links support `from=home` or `from=hardware`, `interest=grip-one|tactile-gloves|data`, and an optional `utm_campaign` label containing only letters, digits, underscores and hyphens (80 characters maximum). Never put an email, name, or sensitive identifier in a tracking URL. Form content is sent in the POST body, not the URL.
